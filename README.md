# Stock Analysis

> **폴더 이름을 바꾸고 싶다면** GitHub 저장소 Settings → 맨 위 Repository name 을
> `stock-analysis` 로 바꾸면 됩니다. 그 뒤로 내려받는 ZIP 폴더 이름도 따라 바뀌고,
> 업데이트 기능은 바뀐 이름을 알아서 따라갑니다(`.git` 설정에서 읽습니다).


관심 종목의 **SEC EDGAR 공시(8-K, Form 4)** 를 주기적으로 확인해서 새 공시가 뜨면 **텔레그램**으로 알려주는 봇입니다.
덤으로 **미국 증시 휴장일**, **주요 경제지표 일정과 지금 값(CPI·금리·고용)**, 그리고 정리해둔 판단 기준(가이던스 > 어닝 서프라이즈 > 마진 방향)에 맞춘 **재무 지표 체크리스트**를 같이 보내줍니다.

외부 유료 API 없이 **SEC 공식 무료 API**(EDGAR submissions / XBRL companyfacts)와 무료 시세(Stooq · Yahoo Finance), 세인트루이스 연준(FRED) 공개 자료만 씁니다. API 키가 필요 없습니다.

## 폴더 안에 뭐가 있나

폴더를 열면 **누르는 파일만** 보입니다.

| 파일 | 무엇 |
|---|---|
| **시작하기.bat / .command** | ⬅ **이걸 더블클릭하면 됩니다** |
| **업데이트.bat / .command** | 최신 코드로 갱신 |
| **끄기.bat / .command** | 감시를 멈춥니다 |
| README.md | 이 문서 |
| `program/` | 나머지 전부 — **열어보실 일이 없습니다** |

프로그램이 돌아가는 데 필요한 것은 전부 `program/` 안에 들어 있습니다.
설정과 기록도 거기 있습니다.

| `program/` 안 | |
|---|---|
| `config.yml` | 내 설정. 처음 실행하면 물어보면서 자동으로 만들어집니다 |
| `logs/실행기록.log` | 창 없이 도는 동안 무슨 일이 있었는지 |
| `stock_analysis/` | 프로그램 본체 |
| `main.py` · `bootstrap.py` · `updater.py` | 실행·준비·갱신 |
| `data/` | FOMC 일정 같은 고정 자료 |
| `tests/` | 자동 검사. **지우지 마세요** — 코드를 고칠 때 뭐가 깨졌는지 잡아주는 안전장치입니다 |

> 예전 버전을 쓰시던 분은 그냥 **업데이트**만 누르시면 됩니다.
> 바깥에 흩어져 있던 설정·기록을 `program/` 안으로 알아서 옮기고 예전 파일은 치웁니다.
> 다시 물어보는 것도, 없어지는 것도 없습니다.

> 아래 설명에 나오는 `python main.py ...` 같은 터미널 명령은 모두 **`program` 폴더 안에서** 실행합니다.
> (`cd program` 을 먼저 한 번 하시면 됩니다)

## 0. 가장 쉬운 방법 — 더블클릭

터미널을 몰라도 됩니다. 이 저장소를 받은 폴더에서 운영체제에 맞는 파일을 **더블클릭**하세요.

| 운영체제 | 시작할 때 | 멈출 때 | 최신 버전으로 갱신할 때 |
|---|---|---|---|
| 윈도우 | **`시작하기.bat`** | **`끄기.bat`** | **`업데이트.bat`** |
| 맥 / 리눅스 | **`시작하기.command`** | **`끄기.command`** | **`업데이트.command`** |

> **자동 업데이트**: 봇이 하루에 한 번 새 버전이 나왔는지 확인해서, 있으면 **화면 위에 배너**를 띄우고 텔레그램으로도 알려줍니다.
> 배너의 **지금 업데이트** 버튼을 누르면 그 자리에서 갱신됩니다(설정·기록은 그대로). `업데이트` 파일 더블클릭도 같은 일을 합니다.
> **`업데이트` 는 돌고 있어도 그냥 누르시면 됩니다.** 알아서 잠깐 멈추고, 갱신하고, 다시 켭니다.
> 버전은 화면 맨 아래에 표시됩니다.
>
> ⚠️ **저장소가 비공개(private)면 자동 업데이트가 막힙니다.** 로그인 없이 내려받을 수 없기 때문입니다.
> 셋 중 하나를 고르시면 됩니다.
> ① GitHub 저장소 **Settings** 맨 아래 → **Change visibility** → **Public** (가장 간단, 설정 파일은 저장소에 없으니 공개돼도 개인 정보는 안 나갑니다)
> ② 비공개 유지 → **`업데이트` 를 실행하면 막힌 자리에서 토큰을 물어봅니다.** 붙여넣으면 확인하고 저장한 뒤 바로 이어서 받습니다.
>    (토큰 만들기: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained → 이 저장소만, Contents: Read-only)
> ③ 그때그때 → GitHub 에서 **Code → Download ZIP** 받아 폴더에 덮어쓰기

처음 한 번만 이렇게 진행됩니다.

1. 파이썬이 있는지 확인하고, 없으면 설치 주소를 알려줍니다
2. 필요한 패키지를 알아서 설치합니다 (1~2분)
3. **이름·이메일 / 텔레그램 토큰 / 감시할 종목**을 차례로 물어봅니다 — 답만 하면 `config.yml`이 만들어집니다
4. **검은 창이 스스로 닫히고**, 브라우저에 대시보드가 뜹니다

두 번째부터는 더블클릭 → 바로 대시보드입니다.

### 검은 창은 안 남습니다

질문에 답해야 하는 동안만 창이 떠 있고, 준비가 끝나면 **감시는 창 없이 뒤에서 계속 돕니다.**
실수로 창을 닫아 감시가 멈추는 일이 없고, 화면에도 창이 안 쌓입니다.

| | |
|---|---|
| 멈추기 | 화면 오른쪽 위 **⏻ 종료** 버튼, 또는 **`끄기`** 파일 더블클릭 |
| 이미 켜져 있을 때 `시작하기` 를 또 누르면 | 두 개가 뜨지 않고 **화면만 다시 열립니다** |
| 무슨 일이 있었는지 보기 | `program/logs/실행기록.log` — 창에 뜨던 내용이 여기 그대로 쌓입니다 |

> **폴더가 "사용 중인 폴더" 라며 안 지워진다면** 감시가 아직 돌고 있는 것입니다.
> 창이 없을 뿐 프로그램은 살아 있고, 윈도우는 실행 중인 프로그램의 폴더를 붙잡아 둡니다.
> **⏻ 종료** 를 누르거나 `끄기` 를 실행한 뒤에 지우시면 됩니다.
> `끄기` 는 적어둔 번호가 없어도, 설정 파일이 지워졌어도, 여러 개가 떠 있어도
> 이 폴더의 프로그램을 직접 찾아서 멈추고 **정말 멈췄는지 확인한 뒤에** 멈췄다고 말합니다.
> 그래도 안 되면 작업 관리자(`Ctrl+Shift+Esc`)에서 **pythonw.exe** 를 끝내거나,
> 컴퓨터를 다시 켜면 확실히 정리됩니다.

화면이 안 뜨면 `program/logs/실행기록.log` 를 열어보시고, SEC 접속이 막힌 것 같으면
터미널에서 `python main.py doctor` 로 어디까지 되는지 확인할 수 있습니다.

### 설정을 잘못 넣었다면

**다시 실행하면 잘못된 항목만 다시 물어봅니다.** 설정 파일이 있다는 이유로 그냥 넘어가지 않습니다.

특히 **이메일**을 조심해주세요. SEC 는 연락처가 담긴 접속 정보를 요구하는데, 여기에 이메일이
아닌 값이 들어가면 **프로그램은 뜨지만 SEC 가 전부 막아서 화면이 통째로 빕니다.**
그래서 `ID@도메인.com` 형식이 아니면 아예 저장하지 않고 다시 묻습니다.

값을 직접 바꾸고 싶으면 터미널에서 `python main.py setup` → **1) 값을 다시 입력해서 고치기**.
나머지 설정과 주석은 그대로 둔 채 해당 줄만 바뀝니다.

> **맥에서 "확인되지 않은 개발자" 경고가 뜨면**: `시작하기.command` 를 우클릭 → **열기** → **열기** 버튼. 처음 한 번만 하면 됩니다.
>
> 텔레그램은 **건너뛰어도 됩니다.** 그럼 알림 없이 대시보드 화면으로만 봅니다. 나중에 `config.yml`에 토큰을 넣으면 켜집니다.

### 미국 · 한국 — 화면이 나뉘어 있습니다

화면 위의 **미국 / 한국** 단추로 오갑니다. 한 화면에 섞지 않은 이유는 **두 시장이 보는 자료가 아예 다르기 때문**입니다.

| | 미국 | 한국 |
|---|---|---|
| 공시·재무제표 | SEC EDGAR — **무료, 열쇠 불필요** | 금융감독원 **DART — 무료지만 인증키 필요** |
| 주가 | Stooq · Yahoo | Yahoo (`005930.KS`) — 열쇠 불필요 |
| 재무 기준 | 최근 **4개 분기 합산**(TTM) | 사업보고서의 **연간 확정치** |

**한국 종목 넣는 법**: **회사 이름을 그대로** 적으면 됩니다. 여섯 자리 숫자를 외우실 필요 없습니다.

```yaml
watchlist:
  - ticker: AAPL
  - ticker: 삼성전자        # ← 이름 그대로
  - ticker: 카카오
```

화면의 **종목 추가** 칸에도 `삼성전자` 라고 치면 됩니다.

코드로 넣어도 됩니다 — `005930`, `005930.KS`, `A005930` 다 받습니다. 다만 **숫자로 넣을 땐 따옴표를 꼭** 붙이세요(`"005930"`). 없으면 앞의 0이 사라져 `5930` 으로 읽힙니다.

> **이름 찾기에는 DART 인증키가 필요합니다.** 회사 이름 목록을 DART 에서 받아오기 때문입니다. 키가 없으면 코드로 넣으셔야 합니다.
>
> **비슷한 이름이 여럿이면 고르라고 합니다.** `삼성` 이라고 치면 *"삼성전자(005930) · 삼성물산(028260) · 삼성SDI(006400) 중 하나를 골라주세요"* 라고 나옵니다. 비슷하다고 아무거나 고르면 엉뚱한 회사를 감시하게 되니까요.

**DART 인증키** (무료·1분): [opendart.fss.or.kr](https://opendart.fss.or.kr) → 인증키 신청 → 받은 키를 `config.yml` 의 `dart_api_key` 에 넣습니다.

> **키가 없어도 주가는 보입니다.** 재무제표만 비고, 화면이 왜 비었는지 그 자리에 적힙니다. 잘 받아지는지는 `python main.py doctor` 로 확인하실 수 있습니다.

**한국 화면에서 아직 안 되는 것** (화면에도 그대로 적혀 있습니다)

- **PER · PSR** — 시가총액을 구하려면 발행주식수가 필요한데 아직 받지 않습니다. 밸류에이션은 '판단 불가'로 둡니다. **지어내지 않습니다.**
- **눈여겨볼 종목(추천)** — 미국 화면에만 있습니다. SEC 는 전체 기업의 매출을 한 번에 주기 때문에 후보 순위를 만들 수 있는데, DART 에는 그런 창구가 없습니다.
- **휴장일 · 경제지표 · 번역** — 미국 기준이라 미국 화면에만 둡니다.

**한국 화면에서 되는 것**: 주가 · 등락 · 52주 위치 · **재무제표 판정(다섯 축)** · 체크리스트 · 내 매수가 손익 · **DART 공시 감시**. 판정은 미국과 **똑같은 잣대**를 씁니다.

#### DART 공시 — 진짜 중요한 것만

DART 에는 하루에도 수십 건이 올라옵니다. 전부 알리면 알림이 소음이 되고, 소음이 되면 **정작 중요한 것을 놓칩니다.** 그래서 주가에 실제로 영향을 주는 것만 골라 등급을 매깁니다.

| 등급 | 무엇 |
|---|---|
| 🚨 | 유상증자 · 전환사채(CB) · 신주인수권부사채(BW) · 감자 · **매출·손익 30% 이상 변동** · 회생절차 · 상장폐지 · 거래정지 · 최대주주 변경 · 합병 · 분할 · 영업양수도 |
| 🟠 | 자기주식 취득/처분/소각 · 배당 · **단일판매·공급계약(수주)** · 소송 · 사업/반기/분기보고서 · 5% 대량보유 |
| 🟡 | 그 외 (임원 지분 변동 등) |

**공시마다 "무엇을 봐야 하는지"가 붙습니다.** `유상증자결정` 다섯 글자만으로는 좋은 일인지 나쁜 일인지 알 수 없습니다.

> 🚨 **005930** 유상증자 결정
> *주요사항보고서(유상증자결정)*
> 👉 새 주식을 찍어 파는 것입니다. 발행주식수가 늘어 내 몫이 줄어듭니다. 얼마를 어디에 쓰는지, 할인율이 얼마인지를 보세요.

**DART 가 붙인 원래 이름도 항상 함께 보여줍니다.** 저희가 붙인 제목이 틀렸을 때 알아채실 수 있어야 하니까요. 규칙에 없는 공시는 억지로 등급을 매기지 않고 원래 이름 그대로 '참고'로 둡니다 — 안 중요한 게 빨갛게 뜨면 빨간색을 안 믿게 됩니다.

#### 장 시작 / 마감

**미국 / 한국** 단추에 지금 장이 열려 있는지가 함께 뜹니다 (🟢 장중 / ⚫ 장 마감 / 🌙 장 시작 전).

> **휴장일 표를 손으로 적지 않았습니다.** 설날·추석은 음력이라 해마다 날짜가 바뀌는데, 그걸 적어 넣으면 틀린 날 '장중'이라고 말하게 됩니다. 대신 **시세 제공처(거래소)가 알려주는 상태를 그대로** 씁니다 — 휴장일도 자동으로 맞습니다. 시세를 못 받았을 때만 시각으로 어림하고, 그때는 `~장 마감` 처럼 **물결표로 어림임을 표시**합니다.

### 대시보드에서 할 수 있는 것

브라우저에 뜨는 화면(`http://127.0.0.1:8765`)에서:

**① 전체 종목 한눈에 (표)** — 종목별 한 줄로 나란히 비교
> 상황 판정 | 주가·등락 | 시총 | 매출(TTM) | 매출성장 | 영업이익률(↑↓) | ROE | ROIC | PER | PSR | 런웨이 | 체크(✅⚠️❌) | 실적발표 D-day

**② 지금 상황** — 종목마다 **다섯 축**으로 판정합니다.
> 성장 · 수익성 · 재무 안정성 · 현금 창출력 · 밸류에이션 → 각각 🟢양호 / 🟡보통 / 🔴주의 / ⚪판단불가

각 판정 아래에 **그렇게 판단한 숫자가 그대로 붙습니다.** "성장 양호"라면 그 밑에 `TTM 매출 $769M (직전 1년 $520M) · 성장률 +47.9%` 가 함께 나옵니다. 데이터가 없으면 추측하지 않고 **판단 불가**로 두고 왜 없는지 밝힙니다.

**③ 분기보고서 내용** — 최신 10-Q/10-K 원문에서 **회사가 쓴 문장을 그대로** 가져옵니다.
- 사업 개요 (Item 1) — 이 회사가 무엇을 하는가
- 위험 요인 (Item 1A) — 회사가 스스로 밝힌 위험
- 경영진 논의(MD&A) — 개요 / 실적 분석 / 현금 사정 / **전망**
- "회사가 직접 밝힌 내용" — 숫자·계획·전망이 담긴 문장만 골라 `[변화] [계획] [전망] [자금]` 라벨로

> **요약을 지어내지 않습니다.** 원문 발췌 + 출처 링크만 보여줍니다. 매출이 왜 늘었는지, 앞으로 뭘 할 예정인지는 회사 본인의 말로 읽으시는 게 정확합니다.

**④ 핵심 숫자 + 추이** — 12개 항목과 최근 8개 분기 막대그래프(매출·영업이익률·순이익). 현재값만으로는 안 보이는 **방향**을 봅니다.

**⑤ 용어 사전** — 화면의 모든 지표에 <sup>?</sup> 가 붙어 있고, 누르면 해당 설명으로 이동합니다. 항목마다 **무엇인지 / 계산식 / 읽는 법 / 주의점 / 출처**가 적혀 있습니다. 평소에는 접혀 있고, 필요할 때 갈래별로 펼칩니다.

**⑥ 이 숫자들의 출처 · 원문 대조** — 화면의 숫자를 **SEC 원문과 직접 맞춰볼 수 있습니다.**

제 코드에 버그가 없다고 제가 보증할 수는 없습니다. 그럴듯하게 생긴 틀린 숫자가 제일 위험합니다. 그래서 답은 하나뿐입니다 — **원문을 열어 직접 보는 것.**

카드마다 펼치면 이렇게 나옵니다.

> **매출** `Revenues` 최근 4개 분기 합산 (2025-01-01 ~ 2025-12-31) · 10-K = **$403.00B**
> ▾ 더한 분기 4개 보기
>   · 2025-01-01 ~ 2025-03-31 · $90.00B [10-Q 원문]
>   · 2025-04-01 ~ 2025-06-30 · $94.00B [10-Q 원문]
>   · 2025-07-01 ~ 2025-09-30 · $95.00B [10-Q 원문]
>   · 2025-10-01 ~ 2025-12-31 · $124.00B [10-K 원문]

- **덧셈이 눈에 보입니다.** "4개 분기 합산"이라고만 하면 그 말을 믿는 수밖에 없습니다. 더한 분기를 값과 함께 펼쳐서 **직접 검산**하실 수 있게 했습니다.
- **분기마다 그 값이 실린 SEC 공시로 바로 갑니다.** 링크를 열면 실제 10-Q/10-K가 나오고, 거기서 같은 숫자를 찾으실 수 있습니다.
- **없는 링크는 지어내지 않습니다.** 접수번호가 없으면 링크 없이 둡니다. 링크가 없는 것보다 틀린 링크가 나쁩니다.
- **시세는 SEC 자료가 아니라고 따로 밝힙니다.** 재무제표와 같은 칸에 섞어 놓지 않습니다.


> **한 종목만 직접 맞춰보시면 됩니다.** 나머지도 같은 코드가 만든 것이니, 하나가 맞으면 나머지를 믿을 근거가 생깁니다. 그게 제가 드릴 수 있는 가장 정직한 보증입니다.

**⑦ 직접 입력** — 컨센서스(EPS·매출)와 내 메모를 화면에서 바로 저장. 컨센서스를 넣으면 실적 발표 직후 어닝 서프라이즈가 자동 계산됩니다.

> 🟠 **주목** — 실적 서프라이즈, 투자의견 변경, 구조조정, 증자, 계약·수주, 금리·물가
> 🟡 **참고** — 그 외

관심 종목 뉴스(Yahoo 티커 피드), 시장 전체 뉴스(연준 보도자료, Google 뉴스), 그리고 **Investing.com · MarketWatch · CNBC 자체 피드**를 감시 주기마다 확인해 **텔레그램으로도 밀어줍니다.** 제목은 원문 그대로 두고, 왜 그 등급으로 봤는지 근거 표현을 함께 표시합니다.

- **시각은 한국시간** — `08-12 22:00` 과 `12분 전` 을 나란히 보여줍니다. 48시간이 지난 기사는 속보로 치지 않습니다.
- **매체 신뢰도** — 로이터·블룸버그·WSJ·Investing.com 같은 1차 매체는 초록색으로, 처음 보는 매체는 회색 이탤릭으로 표시됩니다. 같은 사건을 여러 곳이 쓰면 **믿을 만한 쪽 기사**를 남깁니다.
- **정렬 순서** — 중요도 → 시장 전체 사안 → 최신순 → 매체 신뢰도. 새 기사가 먼저 오되, 비슷한 시각이면 공신력이 순서를 가릅니다.
- 리스티클·예측·질문형 제목("3 Stocks to Buy…", "Should you buy…?")은 먼저 걸러냅니다.

**⑨ 환율·주요 지수** — 화면 맨 위 한 줄. **1분마다** 따로 갱신됩니다.
> 💱 1달러 = 원 · 엔 · 위안 · 유로 (전부 달러 기준이라 읽는 방향이 같습니다)
> 📈 S&P 500 · 나스닥 · 다우 · VIX(공포지수)

**⑩ ETF** — 티커만 넣으면 됩니다. SEC가 따로 내주는 ETF·펀드 목록까지 함께 봐서 `SPY` `QQQ` 같은 지수 ETF는 물론 `ETHU` `CONL` 처럼 일반 목록에 없는 상품도 찾습니다.

ETF는 회사가 아니라서 매출·ROE·영업이익률이 **존재하지 않습니다.** 빈칸으로 두는 대신 ETF 기준으로 보여줍니다.
> 무엇을 담는가(지수·암호화폐·단일 종목·섹터·채권) | 배수·인버스 여부 | 분산 여부 | 시세 | 보수·추종 오차

**배수 상품은 구조를 정확히 알려줍니다.** `2배 레버리지 · 단일 종목(COIN)` 처럼 성격을 한 줄로 띄우고, *"하루 수익률의 2배를 맞추도록 매일 되맞추는 상품입니다. 이틀 이상 들고 있으면 기초자산이 제자리로 돌아와도 손실이 남을 수 있습니다"* 라고 밝힙니다. 감시하는 서류도 10-Q가 아니라 투자설명서(497·485BPOS)와 연차보고서(N-CSR)로 바뀝니다.

> 운용보수는 **지어내지 않습니다.** 투자설명서 링크를 주고 직접 확인하시게 합니다.

**⑪ 위험 요인 변화** — 이번 10-Q/10-K의 위험 요인(Item 1A)을 **직전 보고서와 문단 단위로 맞춰봅니다.**

위험 요인은 해마다 거의 같은 문장이 반복됩니다. 그래서 **회사가 어떤 위험을 처음 적어 넣는 순간**이 중요합니다. 표현만 다듬어진 문단은 같은 것으로 보고, 진짜 새로 들어온 문단만 원문 그대로 보여줍니다.

특히 무거운 표현에는 이름표가 붙습니다.
> 존속 의문 · 내부통제 미비 · 재무제표 재작성 · 상장폐지 통보 · 채무 약정 위반 · 추가 자금 필요 · 핵심 고객 이탈 · 당국 조사

각 이름표 아래에 **그게 무슨 뜻인지**와 회사가 쓴 문장이 함께 나옵니다. 예를 들어 "존속 의문"이면 *"회사가 '계속기업으로서 존속할 수 있을지 중대한 의문'이 있다고 밝혔습니다. 감사인이 이 문구를 붙이면 자금 조달이 급해졌다는 뜻입니다."*

**⑫ 내부자 거래** — Form 4를 **90일 단위로 묶어서** 봅니다.

한 건씩 보면 뜻을 알기 어렵습니다. 임원이 RSU를 받아도, 세금 내려고 주식을 반납해도 전부 Form 4로 올라오기 때문입니다. 그래서 **자기 돈으로 산 것(P)과 시장에 내다 판 것(S)만** 셉니다.

> 최근 90일 2명이 $2.60M 매수, 1명이 $368.80K 매도 → 순매수 $2.23M

임원 여러 명이 같은 기간에 자기 돈으로 사는 건 드뭅니다. 반대로 매도는 세금·분산·사전계획(10b5-1) 때문일 수 있어 그 자체로 악재라고 쓰지 않습니다.

**⑬ 실적 3자 대조** — 실적이 나온 순간 봐야 하는 건 숫자 하나가 아니라 **세 숫자의 관계**입니다.

| 비교 | 실제 | 기대·약속 | 결과 |
|---|---|---|---|
| 매출 vs 컨센서스 | $246.00M | $240.00M (+2.5%) | ✅ 상회 |
| 매출 vs 가이던스 | $246.00M | $230.00M ~ $240.00M (+2.5%) | ✅ 상회 |

메모의 1순위(가이던스)와 2순위(어닝 서프라이즈)가 여기서 한 화면에 모입니다. 셋 중 없는 게 있으면 없는 대로 두고, 두 개만 있어도 비교합니다.

**⑮ 눈여겨볼 종목 5개** — 지표가 괜찮아 보이는 회사를 화면 앞으로 끌어옵니다.

> **사라는 뜻이 아닙니다.** 공시된 재무제표를 감시 목록과 **똑같은 잣대**로 줄 세워, 직접 들여다볼 만한 것을 앞으로 가져온 것뿐입니다. 카드마다 **왜 뽑혔는지가 숫자로** 적혀 있으니 그 숫자를 먼저 보세요. 마음에 들면 **＋ 감시 목록에 추가** 버튼 한 번으로 감시가 시작됩니다.

**후보 목록을 손으로 적지 않습니다.** 무엇이 후보에 들어가느냐가 곧 무엇을 추천받느냐입니다. 목록에 없는 회사는 아무리 좋아도 영영 안 나오니, 그 결정을 사람 판단에 맡기면 추천 전체가 그 판단을 따라갑니다. 그래서 SEC 가 공개한 자료 두 가지로만 만듭니다.

| 무엇을 | 어디서 |
|---|---|
| 모든 제출 기업의 **연간 매출** | SEC XBRL frames (`data.sec.gov/api/xbrl/frames/...`) — 한 번의 요청으로 전부 |
| 그 기업들의 **실제 티커** | SEC `company_tickers.json` |

매출 상위 300개(설정 가능)를 후보로 삼습니다. 매출을 고른 이유는, 무료로 구할 수 있는 값 중에 *"실제로 장사를 하고 있는 회사"* 를 가리는 데 가장 덜 자의적이기 때문입니다. SEC 에 보고서는 내지만 티커가 없는 회사(비상장·ADR 없음)는 살 수 없으니 빠집니다.

> **받지 못하면 비워 둡니다.** 대신 쓸 목록을 몰래 끼워 넣지 않습니다. 화면에는 *"SEC 에 2025년 매출을 신고한 4,821개 기업 중 매출 상위 300개 (2026-09-02 기준)"* 처럼 **이 목록이 어디서 왔는지**와 *"후보 300개 중 37개 확인"* 처럼 **몇 개를 봤는지**가 항상 적힙니다.
>
> 잘 받아지는지는 터미널에서 `python main.py doctor` 로 직접 확인할 수 있습니다.
>
> **"키를 넣었는데 없다고 한다"** 면 `doctor` 가 이유를 짚어줍니다 — 어느 파일을 읽었는지, 줄 앞에 `#` 이 붙었는지, 빈칸이 들어갔는지. **키 값 자체는 절대 찍지 않습니다**(길이와 앞뒤 두 글자만). 결과를 캡처해서 보내셔도 안전합니다.

**세 갈래로 나옵니다.** 묻는 질문이 서로 다르기 때문입니다. 한 줄로 세우면 답이 섞입니다.

| 갈래 | 무엇을 묻나 | 무엇으로 보나 | 꼭 함께 읽을 것 |
|---|---|---|---|
| **탄탄한 회사** | 지금 돈을 잘 벌고 재무가 튼튼한가 | 다섯 축 + 마진 방향 + ROIC | 지금까지의 재무제표 이야기입니다. 앞으로도 그러리라는 보장은 없습니다 |
| **성장 가능성** | 빠르게 커지고 있는가 | 매출 성장률 + 남은 현금(런웨이) + 손실이 줄고 있는가 | **적자여도 들어옵니다.** 돈이 떨어지면 증자로 내 몫이 줄고, 성장이 꺾이면 크게 빠집니다 |
| **시장 흐름** | 시장이 지금 이걸 사고 있는가 | 최근 3·6개월 주가를 S&P 500 과 비교 | **최근에 올랐다는 사실일 뿐, 앞으로 오른다는 뜻이 전혀 아닙니다** |

한 회사가 여러 갈래에 들어갈 수 있습니다 — 같은 회사를 다른 질문으로 본 것이라, 그게 오히려 정보입니다. **갈래끼리 점수를 견주지는 않습니다.** "탄탄함 22점"과 "시장보다 18%p"는 단위부터 다른 값이라, 나란히 놓는 순간 없는 뜻이 생깁니다.

> **성장 갈래를 따로 둔 이유**: 다섯 축 판정은 흑자 기업에 유리하게 짜여 있어서, 매출이 두 배로 늘고 있어도 적자면 '주의'로 떨어집니다. 그런 회사를 아예 안 보겠다는 것은 판단이 아니라 회피입니다. 대신 적자 기업에 실제로 중요한 것 — 얼마나 빨리 크는가, 버틸 돈이 있는가, 손실이 줄고 있는가 — 을 따로 봅니다. 1년 반도 못 버티는 회사는 성장이 빨라도 넣지 않습니다.

**화면에서는 티커만 먼저 보입니다.** 다섯 개의 근거를 한꺼번에 늘어놓으면 화면 한 판을 다 먹어서, 정작 아래에 있는 공시와 경제 지표가 안 보입니다. **티커를 누르면** 이유가 펼쳐지고, 무엇을 펼쳐 뒀는지는 기억합니다(화면이 스스로 새로고침돼도 그대로 있습니다). 섹션 제목을 누르면 통째로 접힙니다.

**믿고 판단에 쓸 값과, 참고로만 볼 값을 가릅니다.**

같은 SEC 공시에서 나온 숫자라도 다 같은 무게가 아닙니다. 매출·순이익은 회사가 그대로 적어 낸 값이지만, 어떤 값은 그 위에 **나눗셈을 얹은 것**이라 분모가 이상해지면 숫자만 멀쩡하고 뜻은 사라집니다.

> 실제로 겪은 예입니다. 애플이 화면에 *"자본 효율 100.5%"* 로 떴는데, 그건 **자사주를 오래 사들여 자기자본이 쪼그라든 결과**지 사업이 그만큼 좋다는 뜻이 아닙니다. 계산은 맞지만 "끌어다 쓴 돈에 비해 잘 번다"는 말과는 다른 이야기입니다. 이런 값으로 '수익성 양호'를 주면 **맞는 숫자로 틀린 판단**을 하게 됩니다.

그래서 아래 값들은 **점수에서 빼고**, 대신 카드의 **"참고 — 판단에는 넣지 않은 값"** 칸에 왜 뺐는지와 함께 남깁니다. 지우지 않는 이유는 **값이 없는 것과 못 미더운 것은 다르기 때문**입니다. ROE 100%는 그 자체로 "이 회사는 자기자본이 거의 없다"는 정보입니다.

| 뺀 값 | 언제 | 왜 |
|---|---|---|
| ROE · ROIC | 60% 이상이거나 자기자본이 0 이하 | 분모가 무너지면 사업 성과와 무관하게 치솟습니다 |
| 매출 성장률 | 직전 1년 매출이 $20M 미만 | $1M → $3M 도 +200% 입니다. 커지는 속도라 부를 수 없습니다 |
| 현금 런웨이 | 흑자 기업이거나 20년 초과 | 흑자면 질문 자체가 안 맞고, 너무 길면 "돈이 안 줄고 있다"는 뜻입니다 |
| PER | 200배 초과 | 순이익이 겨우 흑자라 분모가 0 에 가까운 것이지, 비싸다는 뜻이 아닙니다 |
| 과거 PER 중앙값 | 항상 | 실적 공개 시점을 **추정**해 주가와 맞춘 값입니다 |
| 발행주식수 증가율 | 기록이 5분기 미만 | 한 번의 증자가 추세처럼 보입니다 |

성장 갈래는 성장률이 판단의 전부라, 그 값을 못 믿겠으면 아예 갈래에 넣지 않습니다. 밑이 작아서 나온 +300%로 "성장주"라고 부르면 그게 곧 거짓말이기 때문입니다.

**판단 기준 (탄탄한 회사 갈래)**

- **다섯 축**(성장·수익성·재무 안정성·현금 창출력·밸류에이션) 중 **셋 이상이 확인돼야** 순위에 올립니다. 자료가 모자란 회사를 "나쁘지 않다"고 읽어 추천하면 아무 근거 없이 종목을 권하는 셈입니다. 확인 못 한 항목은 감점하고 카드에 그대로 적습니다.
- 여기에 메모의 3순위인 **마진 방향**과 **ROIC** 를 얹고, **희석**(발행주식수 증가)은 깎습니다.
- **가이던스·컨센서스 대조는 순위에 넣지 않습니다.** 메모의 1·2순위지만 이 둘은 감시 목록 종목에만 있습니다(가이던스는 공시 원문을 통째로 받아 읽어야 나옵니다). 점수에 넣으면 이미 보고 있던 종목이 그 이유만으로 위로 올라갑니다. 그건 순위가 아니라 편향입니다. 값이 있으면 **[참고]** 로 표시만 합니다.

**ETF 는 추천하지 않습니다.** ETF 를 줄 세우려면 규모나 보수를 알아야 하는데 무료로 공개된 자료에 그게 없습니다. 근거 없이 "이 ETF 가 낫다"고 하느니 아예 다루지 않습니다. 감시 목록에 넣은 ETF 는 지금까지대로 ⑩ 에서 전부 보여줍니다.

> 회사 하나의 재무 원자료가 수 MB~수십 MB 라 한 번에 다 볼 수 없습니다. 감시 주기마다 몇 개씩 보고, 일주일마다 다시 봅니다. **감시 목록이 항상 먼저입니다** — 아직 안 채워진 내 종목이 있으면 후보는 건드리지 않습니다. 본 결과는 `program/.cache/screen.json` 에 남아서 껐다 켜도 처음부터 다시 하지 않고, 재무 원자료는 계산이 끝나면 지웁니다(300개를 쌓아두면 1GB 가 넘습니다).

**⑭ 52주 위치와 가격 알림** — 최근 1년 최고·최저와 지금 위치를 표시합니다. **52주 신고가·신저가**를 찍거나 하루에 ±7%(설정 가능) 넘게 움직이면 텔레그램으로 알립니다. 같은 날 같은 사유는 한 번만 옵니다.

**⑮ 내 보유** — 매수가와 수량을 넣으면 평가손익을 **달러와 원화 둘 다** 보여줍니다.
> 💼 내 보유 **+$1,176.00** (+25.52%) · 원화 **163만원** (지금 환율 ₩1,382.40 기준)

미국 주식은 두 번 움직입니다. 주가가 오르고, 환율이 또 움직입니다. 달러로는 벌었는데 원화로는 덜 벌 수도 있어서 나눠서 보여줍니다. 화면의 **직접 입력**이나 텔레그램 `/buy RKLB 38.40 120` 으로 넣습니다.

**⑯ 경제 지표 — 지금 값** — 일정은 "언제 나오나"만 알려줍니다. 여기는 **지금 얼마인가**를 보여줍니다.

| | 보여주는 것 |
|---|---|
| 물가 | 소비자물가 CPI · 근원 CPI · 근원 PCE |
| 금리 | 기준금리 · 10년물 국채금리 · 장단기 금리차(10년−2년) |
| 고용 | 실업률 · 비농업 고용 |

> 소비자물가 CPI **2.9%** ▼ -0.2%p · 2026년 7월분
> *목표에 근접* — 물가가 1년 전보다 얼마나 올랐나. 높으면 금리 인하가 멀어진다.

읽는 방향을 세 가지로 고정했습니다.
- **CPI·PCE 같은 지수는 반드시 전년 대비 %로만** 봅니다. 지수 숫자(310 같은)는 그 자체로 아무 뜻이 없습니다.
- **기준 시점을 항상 같이 적습니다.** 8월에 보는 CPI는 7월분입니다. 이 사실이 숫자보다 중요할 때가 있습니다.
- **화살표 색은 방향이 아니라 뜻을 따라갑니다.** 물가가 내려가면 화살표는 아래지만 주식에는 유리하므로 초록입니다. 실업률·고용처럼 해석이 갈리는 값은 색을 칠하지 않고 회색으로 둡니다.

값은 **세인트루이스 연준(FRED)** 에서 받습니다. 열쇠가 필요 없고, 미 노동통계국·상무부·연준이 발표한 원본이 그대로 올라오는 곳입니다. 6시간마다 갱신하고, **받지 못하면 그 칸을 비워 둡니다** — 추정치를 대신 넣지 않습니다. 같은 세 줄이 데일리 브리핑에도 들어갑니다.

### 영어 원문은 한글로 읽습니다

SEC 공시는 전부 영어입니다. 그래서 **한글을 위에, 영어 원문을 접어서 아래에** 둡니다. 원문을 지우지는 않습니다 — 정확한 건 언제나 회사가 쓴 문장입니다.

한글은 두 겹으로 만듭니다.

**① 규칙으로 옮기기 (네트워크 불필요, 숫자를 손대지 않음)**
공시 문장은 생각보다 정형적입니다. 회사가 달라도 뼈대가 같아서 뜻을 지어낼 여지 없이 옮길 수 있습니다.

| 원문 | 한글 |
|---|---|
| Revenue increased 78% year over year to $213.0 million. | 매출 $213.0M — 전년 대비 78% 증가 |
| Net loss was $33.0 million compared to a net loss of $48.0 million. | 순손실 $33.0M — 비교 대상 $48.0M |
| Gross margin improved to 32.5% from 28.1%. | 매출총이익률 28.1% → 32.5% (개선) |
| We ended the quarter with $420.0 million in cash. | 기말 현금 $420.0M |
| Backlog of $1.1 billion. | 수주잔고 $1.1B |
| We expect revenue ... $230 million to $240 million. | 다음 기간 매출 전망 $230M ~ $240M |

**규칙에 없는 문장은 억지로 옮기지 않습니다.** 그래야 지어낸 말이 안 생깁니다.

**② 위험 요인은 '무엇에 관한 위험인지'로**
위험 요인 문단은 길고 늘 같은 꼴이라("We may ... If we fail to ..., our business could be materially and adversely affected") 통째로 옮기는 대신 한글 주제를 붙입니다.
> 공급망 · 자금 조달 · 고객 집중 · 경쟁 · 규제·인허가 · 소송 · 사이버 보안 · 지식재산 · 인력 · 제품 결함·사고 · 환율 · 경기·금리 · 무역·지정학 · 차입금 · 희석 · 회계·내부통제 · 재해·기후 · 주가 변동 · 인수합병 · 세금

**③ 나머지는 번역기 — 아무것도 안 하셔도 됩니다**

규칙으로 못 옮긴 문장만 번역기에 보냅니다. **열쇠(API 키) 없이 쓰는 무료 번역이 기본으로 켜져 있어서, 설치하고 켜면 그냥 한글이 나옵니다.**

더 정확한 번역을 원하시면 열쇠를 하나 넣으시면 됩니다. 화면의 **번역 설정** 칸에서 붙여넣으면 끝이고, config 파일은 안 여셔도 됩니다.

> 1. https://www.deepl.com/pro-api 에서 무료 가입 (월 50만 자)
> 2. 받은 열쇠를 복사
> 3. 화면 아래 **번역 설정 → DeepL → 열쇠 붙여넣기 → 저장**
> 4. **번역 시험** 을 눌러 실제로 되는지 확인

열쇠를 넣으면 그때부터 그걸 먼저 씁니다. 한도가 끝나거나 막히면 **자동으로 다음 번역기로 넘어갑니다** — 화면이 비는 일은 없습니다.

| 순서 | 번역기 | 열쇠 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | **DeepL** | 무료 월 50만 자 | 금융·법률 문장에 가장 강합니다 |
| 2 | **Azure 번역기** | 무료 월 200만 자 | 잘 끊기지 않습니다 |
| 3 | **파파고** | 네이버 클라우드 | 한국어 표현이 가장 자연스럽습니다 |
| 4 | Google 번역 API | 유료 | 정식 API |
| 5 | 무료 경로 | 없음 | 열쇠 없이 되지만 언제든 막힐 수 있어 맨 뒤 |

**어느 번역기가 옮겼는지 문장마다 표시됩니다** — `DeepL 번역`, `파파고 번역`, `무료 번역`. 어디까지 믿을지 직접 정하시라는 뜻입니다.

열쇠는 이 컴퓨터의 설정 파일(`watchlist.local.yml`)에만 저장되고 어디로도 보내지 않습니다. 환경변수(`DEEPL_API_KEY` 등)로 넣어도 됩니다.

**금융 용어는 따로 굳혔습니다.** 번역기는 `revenue`를 "수익", `guidance`를 "지침", `backlog`를 "밀린 주문", `material weakness`를 "중대한 약점"으로 풀어버립니다. 뜻은 맞지만 주식 화면에서는 읽기 나쁩니다. 그런 것만 우리가 쓰는 말로 되돌립니다 — **매출 · 가이던스 · 수주잔고 · 중대한 결함 · 외부감사인 · 영업 실적**.

말을 바꾸면 조사도 같이 고칩니다. "지침**을**" → "가이던스**를**" (받침이 없으니 를).

뜻이 다른 자리는 건드리지 않습니다. `수익률`·`수익성`·`순수익`·`영업 수익`·`이자 수익`은 그대로 둡니다.

번역이 부담스러우면 통째로 끌 수 있습니다. 끄면 규칙으로 옮긴 한글만 나오고 나머지는 원문만 보입니다.

### 자주 나오는 질문

**Q. 가이던스는 왜 자동으로 못 가져오나요?** → 이제 가져옵니다.

회사는 실적을 발표할 때 8-K에 보도자료(Exhibit 99.1)를 붙이고, 그 안에 *"we expect revenue of $120 million to $130 million"* 같은 문장이 그대로 들어 있습니다. 봇이 그 문장을 찾아 **범위를 숫자로 뽑고 원문도 함께** 보여줍니다.

표현이 회사마다 달라 **100% 잡아내지는 못합니다.** 못 찾으면 "찾지 못했다"고 밝히고 원문 링크를 줍니다.

**Q. 그럼 가이던스를 지켰는지는 어떻게 아나요?** → 이것도 자동으로 맞춰봅니다.

가이던스는 **회사가 관리할 수 있는 숫자**입니다. 낮게 불러 나중에 초과 달성하거나, 정의를 바꾸거나, 강조점을 옮깁니다. 그래서 메모에 적힌 대로 **과거 이행 이력**을 봅니다.

봇이 과거 실적 발표문(최근 6개)에서 회사가 제시한 매출 범위를 모으고, 그 분기가 지난 뒤 **SEC에 실제로 제출된 매출**과 나란히 놓습니다.

| 발표일 | 대상 분기 | 가이던스 | 실제 매출 | 결과 |
|---|---|---|---|---|
| 2025-11-10 | 2025-12-31 | $170.0M ~ $180.0M | $246.0M (+36.7%) | ✅ 상회 |

`확인된 3번 중 3번 지켰습니다` 처럼 요약이 붙고, 회사가 쓴 문장 원문도 함께 볼 수 있습니다.

**판정하지 않는 경우도 분명히 밝힙니다.**
- **조정 EPS·EBITDA** — 회사가 정의를 정하는 숫자라 SEC 제출 실적과 바로 비교할 수 없습니다
- 대상 분기 실적이 아직 제출되지 않은 경우
- 금액 단위를 확신할 수 없는 문장

**Q. 희석(주식 수 증가)도 보이나요?**

네. 발행주식수의 최근 8개 분기 추이를 막대그래프로, 1년 변화율을 `희석` 칸에 표시합니다. 1년새 15% 넘게 늘면 "지금 확인할 것"에 경고가 올라옵니다. 적자 기업이 증자로 버티는 중인지가 여기서 드러납니다.

**Q. 컨센서스는 어디서 찾나요?**

컨센서스는 **SEC 공시에 없습니다.** 회사가 아니라 증권사 애널리스트들이 만드는 숫자라서요. 봇은 두 단계로 처리합니다.

1. **자동 수집 시도** — Yahoo Finance에서 가져옵니다. 되면 예상 EPS·매출·애널리스트 수와 과거 서프라이즈 이력까지 표시합니다.
2. **막히면 직접 입력 안내** — 화면에 아래 링크가 뜹니다. 확인해서 "직접 입력"에 넣으면 그 뒤로는 실적 발표마다 자동 비교합니다.

| 어디서 | 무엇을 보면 되나 |
|---|---|
| Yahoo Finance → Analysis | Earnings Estimate 표의 **Current Qtr** 열 Avg. Estimate |
| Nasdaq → Earnings | Quarterly Earnings Surprise 아래 **Consensus EPS Forecast** |
| Zacks → Detailed Estimates | Next Report 의 **Consensus Estimate** |
| StockAnalysis → Forecast | EPS Forecast 표 |

**Q. 동종업계는 어떻게 고르나요?**

SEC가 회사마다 붙여둔 **산업분류 코드(SIC)** 로 같은 업종 상장사를 찾습니다. 임의로 "비슷해 보이는 회사"를 고르지 않고, SEC가 같은 업종으로 분류한 회사만 씁니다. 화면에 어떤 분류인지(`SIC 3760 · Guided Missiles & Space Vehicles`) 함께 표시합니다. 기본 4개까지 자동으로 잡고, `peers` 를 직접 지정하면 그쪽이 우선합니다.

**Q. 장외 가격도 보이나요?**

네. 프리마켓·애프터마켓 가격과 등락률이 정규장 가격 아래 함께 표시됩니다. 지금이 장전인지 정규장인지 장후인지도 함께요. (Yahoo Finance 기준)

**Q. 실제 공시로 제대로 추출되는지 어떻게 확인하나요?**

이 명령이 그걸 위한 것입니다.

```bash
python main.py report RKLB          # 한 종목
python main.py report               # watchlist 전체
python main.py report RKLB --full   # 자르지 않고 전부
```

실제 SEC 원문을 받아와서 **어떤 항목이 잡혔고 무엇이 빗나갔는지** 콘솔에 그대로 찍어줍니다. 보고서 항목, 가이던스 문장, 업종 분류, 컨센서스까지 한 번에 확인할 수 있고, 실패한 항목은 원문 링크를 함께 줍니다.

> **구조적으로 안전한가?** 재무 수치(XBRL)는 SEC가 정한 표준 태그라 안전합니다. 반면 **보고서 본문 추출은 HTML 구조에 의존**해서 회사마다 빗나갈 수 있습니다. 그래서 ① 못 찾으면 조용히 넘어가지 않고 "찾지 못했다"고 밝히고, ② 항상 원문 링크를 함께 주고, ③ `report` 명령으로 미리 검증할 수 있게 만들었습니다. 빗나가더라도 **틀린 정보를 지어내지는 않습니다.**


### 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| **검은 창이 떴다가 바로 사라짐** | 예전 버전의 `.bat` 이 유닉스 줄바꿈으로 저장돼 cmd.exe 가 읽지 못하던 문제입니다. **지금 버전을 다시 받으면 해결됩니다.** |
| **"Python is not installed" 이 뜸** | 설치 페이지가 자동으로 열립니다. 설치 화면 맨 아래 **"Add Python to PATH"** 를 반드시 체크하세요. 이걸 빠뜨리면 설치해도 계속 못 찾습니다. |
| **맥에서 더블클릭해도 반응 없음** | `시작하기.command` 우클릭 → **열기** → 다시 **열기**. 그래도 안 되면 터미널에서 `bash 시작하기.command`. |
| **"프로그램 파일(main.py)을 찾을 수 없습니다"** | ZIP 안에서 바로 실행한 경우입니다. **압축을 먼저 풀고** 그 폴더 안의 시작 파일을 누르세요. |
| **"준비 공간(가상환경)을 만들지 못했습니다"** | 폴더 권한 문제입니다. 바탕화면이나 다운로드 폴더로 옮겨서 다시 시도하세요. 리눅스면 `sudo apt install python3-venv`. |
| **브라우저가 안 열림** | 봇은 정상 실행 중입니다. 주소창에 `http://127.0.0.1:8765` 를 직접 입력하세요. |
| **화면은 뜨는데 종목이 0개, `403 Forbidden`** | SEC가 접속을 거부한 것입니다. 아래 **"SEC 403이 뜰 때"** 를 보세요. |
| **시각이 이상함 / `tzdata` 경고** | 윈도우에는 시간대 데이터가 없습니다. `requirements.txt` 에 `tzdata` 가 포함돼 있으니 다시 받으면 해결됩니다. |

창에 찍힌 오류 메시지가 곧 원인입니다. 그대로 읽어보시면 대부분 해결됩니다.

### SEC 403이 뜰 때

SEC는 자동화된 접속을 막는 방어(WAF)를 두고 있고, **네트워크 환경에 따라 파이썬 요청이 차단**될 수 있습니다. 봇은 헤더 조합을 3가지로 바꿔가며 자동으로 우회를 시도하지만, 그래도 막히면 아래 순서로 확인하세요.

**1단계 — 진단부터**

```bash
python main.py doctor
```

SEC의 여러 주소를 헤더 조합별로 두드려보고 **무엇이 되고 무엇이 막혔는지 표로** 보여줍니다. 이 결과가 원인을 그대로 알려줍니다.

**2단계 — 브라우저로 확인**

브라우저에서 <https://www.sec.gov/files/company_tickers.json> 을 열어보세요.

- **브라우저도 안 열린다** → 네트워크 문제입니다. 백신의 "웹 보호 / HTTPS 검사"를 잠시 끄거나, VPN을 켜고(또는 끄고) 다시 시도하세요. 회사·학교 망이면 그쪽에서 막는 것입니다.
- **브라우저는 열린다** → 아래 3단계가 확실한 우회로입니다.

**3단계 — 티커 목록을 직접 받아두기 (가장 확실)**

브라우저에서 위 주소를 열고 `Ctrl+S`로 **`company_tickers.json`** 이라는 이름으로 **봇 폴더에 저장**하세요. 봇이 그 파일을 최우선으로 사용합니다. SEC에 요청을 보내지 않으므로 차단과 무관하게 동작합니다.

**4단계 — CIK를 직접 넣기**

`data.sec.gov`는 되는데 `www.sec.gov`만 막힌 경우(진단 결과에 나옵니다), 티커 대신 **CIK**를 주면 전부 정상 동작합니다.

화면의 입력창이나 텔레그램에서:
```
RKLB:1819994
```
또는 `config.yml` 에:
```yaml
watchlist:
  - ticker: RKLB
    cik: 1819994
```

CIK는 브라우저에서 <https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&ticker=RKLB> 를 열면 주소창에 `CIK=0001819994` 형태로 보입니다.

### 텔레그램에서 바로

봇에게 메시지를 보내면 즉시 반영됩니다. (`/help` 로 전체 목록)

- 변경 내용은 `config.yml` 이 아니라 **`watchlist.local.yml`** 에 저장됩니다. 손으로 적어둔 주석과 서식이 그대로 남고, 재시작해도 유지됩니다.
- 새로 추가한 종목도 **과거 공시를 쏟아내지 않습니다** (기준선만 잡고 그 다음부터 알림).
- 끄고 싶으면 `telegram_commands: false`.

`config.yml` 을 저장하면 봇이 **변경을 감지해 재시작 없이 다시 읽습니다.** YAML이 깨져 있으면 이전 설정을 그대로 유지하고 로그로만 알려줍니다.

### Form 4 (내부자 거래)

XML 원문을 파싱해서 **누가, 무엇을, 몇 주, 얼마에** 거래했는지까지 보여줍니다.

```
🔴 [Form 4 내부자 거래] NVDA · NVIDIA CORP
👤 Hong Gildong (이사, Chief Executive Officer)
• 공개시장 매도 100,000주 @ $120.50 = $12.05M (2026-08-07) · 거래 후 보유 1,234,567주

➡️ 공개시장 매도 합계 $12.05M — 사전계획(10b5-1) 매도인지 원문에서 확인하세요
```

보상용 RSU 취득(A), 세금 납부용 반납(F), 옵션 행사(M)와 **실제 공개시장 매수(P)·매도(S)** 를 구분해서 표시합니다.

### 데일리 브리핑 (기본 매일 08:00 KST)

- 오늘 미국 증시가 휴장인지 / 조기폐장인지 / 정상 개장인지
- **관심 종목 실적 발표일** (D-day 포함, 맨 위에 따로)
- 다가오는 휴장·조기폐장 일정
- 주요 경제지표 일정
- 관심 종목 지표 한 줄 요약
- FOMC 일정 데이터가 만료돼 가면 갱신하라는 경고

### 실적 발표 리마인더 (D-7 / D-1 / 당일)

메모의 1·2순위(가이던스·어닝 서프라이즈)가 실제로 결정되는 날이라 따로 챙깁니다.

```
🔔 TSLA · Tesla, Inc. 실적 발표가 7일 뒤입니다
📆 2026-10-22(목) (D-7, 추정일)
과거 8-K 2.02 제출 간격으로 추정한 날짜입니다. /earnings 로 확정일을 넣어두면 정확해집니다.

컨센서스를 넣어두면 발표 직후 서프라이즈를 자동 계산합니다: /consensus TSLA eps=1.01
```

## 4. 지표 체크리스트 — 정리해둔 기준 그대로

`python main.py metrics NVDA` 를 실행하면 SEC XBRL 재무데이터로 아래를 자동 계산합니다.

### 우선순위

| 순위 | 항목 | 봇이 하는 일 |
|---|---|---|
| 1순위 | **가이던스** | 자동 추출은 불가. 대신 8-K **2.02 / 7.01** 공시가 뜨면 🚨 로 띄우고 "가이던스와 과거 이행 이력, 현금흐름표를 확인하라"는 안내를 붙입니다 |
| 2순위 | **어닝 서프라이즈** | `config.yml` 에 컨센서스(`consensus_eps`, `consensus_revenue`)를 넣어두면 실제 발표치와 비교해 %까지 계산합니다 |
| 3순위 | **마진 방향** | 영업이익률을 전년 동기와 비교해 ↑/↓ 와 %p 변화를 표시합니다 |

가이던스는 회사가 "관리"할 수 있으니(낮게 부르기, 정의 바꾸기, 강조점 옮기기) 봇이 숫자로 단정하지 않고 원문 확인을 유도합니다.

### 흑자 기업 체크리스트

| # | 항목 | 판정 기준 |
|---|---|---|
| ① | 분기 매출 지속 | 최근 4개 분기 매출이 모두 존재/양수인지 + 최근 분기 YoY |
| ② | 자본 효율 | **ROE 15% 이상**, 판정은 부채까지 포함한 **ROIC** 로 (NOPAT ÷ (자기자본 + 총부채 − 현금)) |
| ③ | 영업이익률 방향 | 전년 동기 대비 상승/하락 |
| ④ | PER 위치 | 과거 5년 PER 중앙값 대비 + `peers` 로 지정한 동종업계 중앙값 대비 |
| ⑤ | 영업현금흐름 > 순이익 | 미달이면 "이익은 나는데 현금이 안 들어옴" 경고 |

### 적자 기업 체크리스트

| # | 항목 | 판정 기준 |
|---|---|---|
| ① | 매출 성장률 | **30% 이상**인지 (무조건 판단) |
| ② | 적자 축소 추세 | 적자가 줄고 있는지. **매출↑인데 적자도↑면 "최악의 조합"으로 표시** |
| ③ | 현금 런웨이 | 보유 현금 ÷ 연간 소진액. **2년 미만이면 '금지'** 로 표시 |
| ④ | PSR 위치 | `peers` 동종업계 중앙값 대비 |
| ⑤ | 핵심 마일스톤 | `config.yml` 의 `milestones` 를 매번 같이 띄워 대조하게 함 |

판정은 ✅ 통과 / ⚠️ 주의 / ❌ 미달 / ➖ 데이터 없음 으로 표시됩니다.

**데이터 출처와 한계 — 정확성 원칙**

이 프로그램은 **숫자도 문장도 지어내지 않습니다.**

| 무엇 | 어디서 | 어떻게 |
|---|---|---|
| 재무 수치 | SEC XBRL companyfacts | 10-Q/10-K 원본. 수정 공시가 있으면 최신본. 10-K만 있는 4분기는 `연간 − 3개 분기`로 역산 |
| 보고서 본문 | SEC EDGAR 원문 | **원문 그대로 발췌**. 요약·의역 없음 |
| 상황 판단 | 위 수치에 규칙 적용 | 모든 결론에 근거 숫자를 함께 표시. 데이터 없으면 "판단 불가" |
| 주가 | Stooq → Yahoo Finance | 종가 기준(실시간 아님). 한 곳이 실패하면 다른 곳으로 |
| 컨센서스 | **직접 입력** | 무료 공개 API가 없습니다. 넣지 않으면 ➖ 로 표시 |
| 가이던스 | **자동 추출 안 함** | 회사가 관리할 수 있는 값이라 원문 확인을 유도합니다 |

계산에 쓴 XBRL 항목명·기간·보고서 종류는 화면의 **"이 숫자들의 출처"** 에서 전부 확인할 수 있습니다.

## 5. 설정 (config.yml)

```yaml
user_agent: "Hong Gildong hong@example.com"   # SEC 필수. 환경변수 SEC_USER_AGENT 권장
forms: ["8-K", "4"]          # 감시할 폼. 10-Q, 10-K, SC 13D 등 추가 가능
poll_interval_sec: 900       # 감시 주기(초)
lookback_days: 3             # 재시작 시 며칠 전 공시까지 훑을지
timezone: "Asia/Seoul"
daily_brief_time: "08:00"    # 끄려면 null
econ_min_importance: 2       # 1=자잘한 것까지, 3=최상급만
econ_include_weekly: false   # 매주 목요일 실업수당 청구건수 포함 여부
earnings_reminder_days: [7, 1, 0]   # 실적 발표 며칠 전에 알릴지 (0=당일)

telegram_commands: true      # 텔레그램 명령(/add, /consensus …) 받기
allowed_chat_ids: []         # 비우면 telegram_chat_id 만 허용
overrides_path: "watchlist.local.yml"   # 명령으로 바뀐 내용을 저장할 파일

dashboard:                   # 내 컴퓨터에서 보는 화면
  enabled: true
  port: 8765
  open_browser: true         # 실행하면 브라우저 자동으로 띄우기

econ_extra_events:           # 확정된 일정은 여기에 (추정일 대신 이 값이 쓰임)
  - date: 2026-08-12
    name: "소비자물가 CPI (7월)"
    time_et: "08:30"
    importance: 3

watchlist:
  - ticker: AAPL             # 가장 간단한 형태

  - ticker: NVDA
    name: "엔비디아"
    forms: ["8-K", "4", "10-Q"]
    peers: ["AMD", "AVGO"]   # PER/PSR 상대 비교 대상
    consensus_eps: 1.01
    consensus_revenue: 45000000000
    earnings_date: 2026-11-18   # 알면 지정, 없으면 자동 추정

  - ticker: RKLB
    milestones:
      - "Neutron 첫 발사"
```

비밀값은 환경변수가 파일 값보다 우선합니다: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SEC_USER_AGENT`.

### 챙기는 일정 목록

| 분류 | 항목 |
|---|---|
| 금리·연준 | FOMC 금리 결정(+점도표), **FOMC 의사록**(회의 3주 뒤), **베이지북**(회의 2주 전), **잭슨홀 심포지엄** |
| 물가 | CPI, PPI, **PCE 물가지수** |
| 고용 | 고용보고서(NFP), **ADP 민간고용**, **JOLTS 구인건수**, 주간 실업수당(옵션) |
| 경기·소비 | ISM 제조업/서비스업 PMI, 소매판매, **미시간대 소비자심리**, 분기 GDP |
| 수급 | 쿼드러플 위칭(3·6·9·12월), **월간 옵션 만기**(그 외 달) |
| 실적 | **관심 종목 실적 발표일**, **어닝시즌 개막**(대형은행) |
| 휴장 | NYSE 정규 휴장일 + 조기폐장(13:00 ET) |

`econ_min_importance` 로 노출 수준을 조절합니다 (3=FOMC·CPI·고용·PCE 급만, 1=전부).

### 경제지표 일정에 대한 솔직한 설명

무료·무인증으로 쓸 수 있는 **확정** 경제지표 캘린더 API가 없습니다. 그래서 두 가지를 섞었습니다.

- **확정**: FOMC 일정은 연준 공식 일정을 `data/fomc.yml` 에 넣어뒀습니다 (2025·2026년). 의사록·베이지북은 여기서 관례대로 파생시킵니다.
- **추정**: 나머지는 발표 기관의 관례로 계산합니다 — 고용보고서는 첫째 금요일, ISM 제조업은 첫 영업일, CPI는 중순, PCE는 월말 등. 메시지에 `(관례 기반 추정일)` 이라고 표시됩니다.

날짜가 중요한 지표는 `econ_extra_events` 에 확정일을 넣어주세요. 같은 달 같은 지표의 추정치를 자동으로 대체합니다 (`소비자물가 CPI (7월)` 처럼 괄호를 붙여도 같은 지표로 인식합니다).

**FOMC 일정이 떨어져 가면 봇이 먼저 알려줍니다.** 마지막 회의까지 60일 미만이 남으면 데일리 브리핑과 `/status` 에 "`data/fomc.yml` 에 다음 연도 일정을 추가하세요"라는 경고가 붙습니다. [federalreserve.gov](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm) 에서 날짜를 복사해 넣고 `python main.py update` 로 받으면 됩니다.

휴장일은 추정이 아니라 **NYSE 규칙 그대로 계산**합니다 (성금요일은 부활절 역산, 토요일 휴일은 금요일 대체, 단 신정이 토요일이면 대체휴장 없음, 준틴스는 2022년부터 등). 조기폐장(13:00 ET)도 포함합니다.

`config.example.yml` 을 `config.public.yml` 로 복사해 **비밀값 없이 watchlist만 남겨** 커밋하면 됩니다.

## 7. 동작 방식 · 주의사항

- **첫 실행은 조용합니다.** 과거 공시를 한꺼번에 쏟아내지 않도록 기준선만 저장합니다. 과거 것도 받고 싶으면 `python main.py check --force`.
- 알림에 성공한 공시만 `state.json` 에 기록합니다. 전송이 실패하면 다음 실행에서 다시 시도합니다.
- 텔레그램 4096자 제한에 맞춰 긴 메시지는 줄 단위로 나눠 보냅니다.
- 네트워크·파싱 오류가 나도 루프는 죽지 않고 다음 주기에 계속합니다.
- EDGAR는 접수 후 공개까지 보통 몇 분 걸립니다. 실시간 체결 알림이 아닙니다.
- 텔레그램 명령은 **등록된 대화방에서만** 받고, 명령 하나가 실패해도 봇은 계속 돕니다.
- 대시보드는 `127.0.0.1` 에만 열리고 외부 접속은 거부합니다. 포트가 쓰이는 중이면 옆 번호로 자동으로 비켜서 엽니다.
- 지표 계산은 무거워서 1시간마다 갱신합니다. 지금 당장 최신 값을 보려면 화면의 **지표 새로고침** 버튼을 누르세요.
- 명령을 켜두면 롱폴링으로 대기하므로 응답이 25초 안에 옵니다. 꺼두면 다음 확인 주기까지 그냥 잠듭니다.
- 실적 발표일 추정은 과거 8-K 2.02 기록이 3회 이상 있어야 하고, 60~120일 간격만 분기 실적으로 인정합니다.
